\subsubsection{Product Backlog}
Para poder cumplir con un trabajo organizado y eficaz cada HU fue dividida en tareas específicas a través de un análisis riguroso y colectivo entre todo el equipo Scrum. Cada tarea fue valorada en términos de prioridad y complejidad utilizando las escalas de valoración que se encuentran en las Tablas \ref{tab:prioridad} y \ref{tab:complejidad}.

La prioridad es el impacto que cada tarea tiene para satisfacer las necesidades del negocio. En este caso el rango fue dado de 1 a 3, siendo 1 la de mayor relevancia y 3 la de menor impacto.

\input{../03Tables/02Chapter/C2.tablePriority}

Por su parte, la complejidad radica en la complejidad que conlleva la ejecución de las tareas, de acuerdo a los recursos utilizados, el tiempo y esfuerzo empleado. El rango fue definido utilizando una vez más la serie de Fibonacci, donde 1 indica una tarea con muy poca complejidad y 8 para las tareas de mayor esfuerzo.

\input{../03Tables/02Chapter/C2.tableComplexity}

\subsubsection{Ejecución del Sprint 0}
En la ejecución de este sprint se llevaron a cabo las siguientes actividades clave:
\paragraph{Definición de arquitectura}
La arquitectura de este middleware fue diseñada utilizando el modelo C4, un enfoque que permite representar la estructura del sistema a través de varios niveles de abstracción.

\subparagraph{Diagrama de Contexto:}
La Figura \ref{fig:diagramaContexto} ilustra el primer nivel del modelo C4 donde se identifica la interacción con los usuarios y sistemas externos. Aquí se aprecian dos tipos de usuarios principales: el administrador del sistema, encargado de gestionar usuarios, supervisar el correcto uso de la aplicación, identificar mejoras en ella y, desarrolladores, principales interesados en utilizar las funciones de traducción y ejecución de consultas.
 
Por otro lado, se establecieron 3 sistemas externos dado que el middleware se conectará a los Sistemas Gestores de Bases de Datos SQL Server y Neo4j para acceder y manipular las bases de datos respectivas y un sistema que brinde el servicio de correo electrónico, necesario para el restablecimiento de contraseñas.

\subparagraph{Diagrama de Contenedores:}
En el diagrama de contenedores de la Figura \ref{fig:diagramaContenedores} se identifican los servicios que componen el sistema, la interacción entre ellos  las tecnologías requeridas para su implementación. Dentro de los contenedores definidos se contempló la interfaz de usuario con la cual los usuarios interactuarán directamente, la api que contendrá la lógica de negocio, un motor de traducción que se encargará del mapeo de sentencias SQL a Cypher, un servicio de logs que registrará toda actividad ejecutada en el \textit{middleware} y la base de datos interna, dedicada al almacenamiento de la información de usuarios, conexiones y consultas.

\paragraph{Definición de base de datos}
De acuerdo a las Historias de Usuario definidas, se optó por implementar una base de datos relacional que contenga la información de los usuarios, la configuración de sus conexiones, las consultas realizadas y para poder dar seguimiento a cada una de las acciones que ejecuten sobre la aplicación. Esta base de datos que será implementada en PostgreSQL contiene 4 tablas principales: \textbf{USUARIOS}, \textbf{CONEXIONES}, \textbf{CONSULTAS} y \textbf{LOGS}, mismas que serán guias para garantizar la integridad de los datos. La Figura \ref{fig:diagramaBaseDatos} ilustra el diagrama de base de datos propuesto con las tablas mencionadas, los campos que contendrán y las relaciones entre ellas.

\subsubsection{Sprint 0 Retrospective}
\begin{itemize}
    \item \textbf{¿Qué salió bien?} \newline
    El diseño de la arquitectura del sistema, las bases de datos y los prototipos de interfaces de usuario en conjunto con el stack tecnológico brindó una orientación para estructurar los repositorios y que puedan ser escalables y mantenibles.

    \item \textbf{¿Qué se puede mejorar?} \newline
    La falta de conocimiento en el uso de Trello retrasó a la configuración inicial de la herramienta que brinda una variedad de herramientas que optimicen la gestión de proyectos y la integración con GitHub. Se propone una capacitación de esta plataforma para sacar provecho de esta aplicación y aumentar la productividad del equipo.
\end{itemize}
