\subparagraph{Cifrado de contraseñas y manejo de sesiones} 
En el servicio de autenticación, se implementó el algoritmo Bcrypt para hashear la contraseña del usuario previo a ser almacenada.

    def get_password_hash(password):
        pwd_bytes = password.encode("utf-8")
        salt = bcrypt.gensalt()
        hashed = bcrypt.hashpw(pwd_bytes, salt)
    return hashed.decode("utf-8")
\end{lstlisting}

Por su parte, para el manejo de sesiones se utilizó JWT, mismo que genera tokens que contiene información del usuario cifrada y un tiempo de expiración. El tiempo de caducidad del token está configurado para 15 minutos y la firma para generación de tokens se obtiene de las variables de entorno con lo cual se refuerza la seguridad del software.

\begin{lstlisting}
    def create_access_token(data: dict, expires_delta: Optional[timedelta]):
        to_encode = data.copy()
        if expires_delta:
            expire = datetime.now() + expires_delta
        else:
            expire = datetime.now() + timedelta(minutes=15)

        to_encode.update({"exp": expire})
        encoded_jwt = jwt.encode(to_encode, JWT_SECRET_KEY, algorithm=ALGORITHM)
    return encoded_jwt
\end{lstlisting}

Finalmente, se expuso esta lógica a través de un endpoint \texttt{/translate}.

\paragraph{Extensión de la Gramática y Lógica de Traducción}
\subparagraph{Funciones de Agregación y Agrupación:}
Se modificó el archivo de gramática \texttt{SQLSimple.g4} para incluir reglas que reconocen funciones de agregación y las cláusulas \texttt{GROUP BY} y \texttt{HAVING}. La clase \texttt{Visitor} fue actualizada para traducir estas construcciones a sus equivalentes en Cypher. Por ejemplo, una función \texttt{COUNT(columna)} se traduce a \texttt{count(n.columna)} y la cláusula \texttt{GROUP BY} se mapea a la cláusula \texttt{WITH} en Cypher para agrupar los resultados.

\subparagraph{Traducción de Relaciones (JOINs):}
Se añadieron reglas a la gramática para los operadores \texttt{INNER JOIN}, \texttt{LEFT JOIN} y \texttt{RIGHT JOIN}. La lógica en el \texttt{Visitor} se extendió para interpretar estas uniones y generar las cláusulas \texttt{MATCH} correspondientes en Cypher que representan las relaciones entre nodos. Por ejemplo, un \texttt{INNER JOIN} entre dos tablas se traduce a un patrón \texttt{MATCH} que conecta dos tipos de nodos.

\subparagraph{Traducción de DML (INSERT, UPDATE, DELETE):}
Finalmente, se extendió la gramática para soportar las sentencias de manipulación de datos.
\begin{itemize}
    \item \texttt{INSERT INTO}: Se traduce a una sentencia \texttt{CREATE} en Cypher para crear un nuevo nodo con las propiedades especificadas.
    \item \texttt{UPDATE}: Se mapea a una combinación de \texttt{MATCH} y \texttt{SET} para encontrar los nodos a actualizar y modificar sus propiedades.
    \item \texttt{DELETE}: Se convierte en una sentencia \texttt{MATCH} seguida de \texttt{DETACH DELETE} para eliminar los nodos y sus relaciones asociadas.
\end{itemize}

\begin{figure}[H]
    \centering
    \begin{lstlisting}[language=Python]
# app/core/parser/visitor.py
class Visitor(SQLSimpleVisitor):
    # ... (metodos existentes) ...

    def visitInsert_statement(self, ctx: SQLSimpleParser.Insert_statementContext):
        # Logica para traducir INSERT a CREATE
        return "CREATE (n:Label {key: 'value'})"

    def visitUpdate_statement(self, ctx: SQLSimpleParser.Update_statementContext):
        # Logica para traducir UPDATE a MATCH y SET
        return "MATCH (n:Label WHERE n.id = 1) SET n.property = 'new_value'"

    def visitDelete_statement(self, ctx: SQLSimpleParser.Delete_statementContext):
        # Logica para traducir DELETE a MATCH y DETACH DELETE
        return "MATCH (n:Label WHERE n.id = 1) DETACH DELETE n"
    \end{lstlisting}

\paragraph{Historial de Consultas}
\subparagraph{Backend:}
Se implementó un mecanismo para guardar cada consulta que un usuario traduce y/o ejecuta. Se creó un nuevo modelo en la base de datos (\texttt{Query}) y un endpoint para que los usuarios puedan recuperar su historial de consultas.

\subparagraph{Frontend:}
Se desarrolló una pantalla de "Historial" que muestra una lista de las consultas realizadas por el usuario. Cada elemento de la lista muestra la consulta SQL original, la consulta Cypher traducida y la fecha en que se realizó. Esto permite a los usuarios reutilizar consultas anteriores fácilmente.

\paragraph{Visualización de Logs}
\subparagraph{Backend:}
Se configuró un sistema de logging para registrar eventos importantes de la aplicación, como inicios de sesión, errores de traducción o consultas ejecutadas. Se creó un endpoint, accesible solo para administradores, que permite recuperar estos logs.

\subparagraph{Frontend:}
Se desarrolló una pantalla de "Logs" en la sección de administración. Esta pantalla muestra los logs en un formato claro y estructurado, permitiendo a los administradores monitorear la salud y el uso del sistema en tiempo real.

\paragraph{Obtención y Exposición de Estadísticas}
\subparagraph{Backend:}
Se desarrolló un nuevo servicio de analíticas (\texttt{analytics\_service.py}) encargado de calcular diversas métricas del sistema. Este servicio realiza consultas a la base de datos para obtener datos como:
